# ChemSpace 3D 모드 도입 분석 보고서

## 1. 개요
현재의 2D 산점도를 확장하여, 3개의 물성을 동시에 시각화할 수 있는 '3D 모드' 도입 가능성을 분석합니다. 사용자가 제공한 `filtered_descriptors.csv` 데이터를 기반으로 Z축 값을 확보하고, 기술적 구현 방안을 검토합니다.

## 2. 데이터 분석 (`filtered_descriptors.csv`)
제공된 CSV 파일에는 약 200여 개의 물리화학적 기술자(descriptors)가 포함되어 있습니다. 3D 시각화를 위한 Z축 후보로 다음 항목들이 적합합니다.

*   **qed (Quantitative Estimate of Drug-likeness)**: 0~1 사이의 값으로, 화합물의 약물 적합성을 나타냅니다. 시각적으로 범위가 명확하여 Z축으로 가장 추천됩니다.
*   **NumRotatableBonds**: 화합물의 유연성을 나타내며, 정수 값이지만 분포 확인에 유용합니다.
*   **FractionCSP3**: 화합물의 포화도를 나타내며 0~1 사이의 값을 가집니다.
*   **HeavyAtomCount**: 화합물의 실질적인 크기를 나타냅니다.

**결론**: `qed` 값을 Z축 기본값으로 사용하고, 사용자 선택에 따라 다른 값을 매핑할 수 있도록 데이터를 보완할 수 있습니다.

## 3. 기술적 구현 방안

### Option A: 현재 페이지 내 통합 (ECharts-GL 사용)
*   **방법**: `echarts-gl` 라이브러리를 추가하여 기존 ECharts 인스턴스에서 `scatter3D` 타입을 사용합니다.
*   **장점**: UI 일관성 유지, 2D/3D 즉시 전환 가능.
*   **단점**: `echarts-gl` 라이브러리 추가 필요(약 1MB+), 3D 렌더링 시 메모리 사용량 증가.

### Option B: 별도 페이지 분리 (`ChemSpace3D.tsx`)
*   **방법**: 3D 전용 분석 페이지를 신설하고 Three.js 기반의 전용 엔진이나 ECharts-GL을 사용합니다.
*   **장점**: 복잡한 3D 조작 UI(회전 제어, 거리 측정 등)를 독립적으로 구성 가능, 성능 최적화 용이.
*   **단점**: 페이지 이동의 번거로움.

## 4. 구현 가능성 확인 결과
*   **데이터 매핑**: 가능. CSV의 SMILES와 현재 JSON의 SMILES가 일치하므로 `qed` 등의 값을 손쉽게 추가할 수 있습니다.
*   **차트 구현**: 가능. `echarts-gl`을 사용하면 현재의 Viridis 테마와 하이라이트 로직을 거의 그대로 3D로 옮길 수 있습니다.

## 5. 제안 사항
현재의 `ChemSpace` 페이지가 이미 복잡해지고 있으므로, **별도 페이지로 분리하거나 탭(Tab) 구조를 도입**하여 3D 모드를 제공하는 것을 추천합니다.

**작업 순서 제안:**
1.  **데이터 업데이트**: `chemSpaceData.json`에 `qed` 필드 추가.
2.  **라이브러리 추가**: `bun add echarts-gl` (Docker 컨테이너 내).
3.  **3D 페이지 구현**: 마우스 드래그로 회전 가능한 3D 공간 구현.
