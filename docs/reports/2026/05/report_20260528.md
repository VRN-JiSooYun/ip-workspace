## Patent Number and Structure Search UX

_Source: `report_20260528_patent_number_structure_search.md`_


## 배경
- My 특허 분석 목록에서 특허 제목 외에 특허 번호와 구조 검색 조건을 frontend에서 backend로 전달해야 한다.
- 구조 검색은 helper API 문서 기준 `smiles`, `type`, `sim` form-data를 사용한다.

## 변경 사항
- 상단 검색 영역에 `특허 제목 / 특허 번호` Segmented 선택을 추가했다.
- 상단 검색 영역을 `특허 제목 / 특허 번호 / 구조 검색` Segmented 선택으로 확장했다.
- 구조 검색 선택 시 입력창을 SMILES 입력 용도로 사용하고, 입력창 옆에 ChemDraw `구조 검색` 버튼을 표시한다.
- ChemDraw에서 구조를 확정하면 생성된 SMILES를 상단 검색 input에 채운다.
- 사용자가 SMILES를 직접 입력한 뒤 `구조 검색` 버튼을 누르면 해당 SMILES를 ChemDraw modal의 초기 구조로 전달한다.
- 검색 타입에 따라 backend 요청 파라미터를 분리했다.
  - 특허 제목: `keyword`
  - 특허 번호: `filter` JSON의 `publication_number` 조건
- 특허 번호 검색 `filter_dict`는 원본 helper HTML 요청 형식에 맞춰 `{"84":[...]}` 형태로 생성한다.
  - `filter_column`: `str#p.publication_number`
  - `filter_condition`: `%s ilike '%%%s%%'`
  - `filter_conjunction`: `and`
  - `filter_group_condition`: 빈 문자열
- 목록 조회 helper payload에 `actionType=GET-PATENT-LIST`, `filter_conjunction=and`를 추가했다.
- 특허 목록 기본 page size를 원본 요청과 맞춰 `25`로 조정했다.
- 상세 필터 패널의 구조 검색 영역은 제거했다.
- 적용된 검색 조건 태그에 특허 번호와 구조 검색 조건을 표시한다.
- backend 목록 조회 DTO와 helper API payload에 `publicationNumber`, `smiles`, `type`, `sim`을 추가했다.
- 실행 중인 backend가 아직 최신 DTO가 아닌 경우에도 특허 번호 검색이 400을 내지 않도록 frontend는 `publicationNumber` 직접 쿼리를 보내지 않는다.

## 참고
- backend 특허 번호 검색은 `publication_number` 컬럼에 `ILIKE` 조건으로 필터를 구성한다.
- 구조 검색은 목록 조회 API와 분리해 `GET /api/patents/compound-search` backend endpoint로 호출한다.
- backend는 helper API에 다음 payload를 전달한다.
  - `wasm=1`
  - `smiles=<SMILES>`
  - `type=substructure`
  - `sim=70`
  - `actionType=GET-ELASTIC-COMPOUND-LIST`
  - `operation=GET-ELASTIC-COMPOUND-LIST`
  - `page=<현재 페이지>`
  - `size=100`
- 원본 compound search form data와 맞추기 위해 `owner_id`는 frontend에서 명시적으로 넘긴 경우에만 helper payload에 포함한다.
- 구조 검색 response를 frontend에서 직접 Patent table row로 변환하는 어댑터 방식은 롤백했다.
- backend가 `GET-ELASTIC-COMPOUND-LIST` 결과의 `compound_id`를 추출한 뒤, 각 compound에 대해 `GET-PATENT-LIST-BY-COMPOUND-ID`를 호출한다.
- backend는 compound별 특허 목록을 합치고 `publication_number` 기준으로 중복 제거한 뒤, 기존 My 특허 분석 목록과 같은 row 형태를 frontend에 반환한다.
- compound별 특허 조회는 외부 API 부하를 줄이기 위해 5개씩 제한된 병렬 호출로 수행한다.
- frontend는 구조 검색 결과도 기존 `mapPatentListItem`만 사용한다.
- 구조 검색 pagination은 원본 helper 동작에 맞춰 page 1은 `GET-ELASTIC-COMPOUND-LIST`, page 2 이상은 `GET-ELASTIC-COMPOUND-LIST-BY-PAGE`를 사용한다.
- 화면 pagination은 helper compound page 단위(`size=100`)로 이동하고, backend가 해당 compound page에서 연결 특허를 모아 현재 화면 row로 반환한다.

## Patent List Pagination Fix Report

_Source: `report_20260528_patent_pagination_fix.md`_


## Date
- 2026-05-28

## Issue
- `GET-PATENT-LIST` pagination이 frontend table에서 정상 동작하지 않았다.

## Cause
- 외부 `patent_analysis_helper_api`는 `total_count`를 숫자가 아니라 `[{ "total": N }]` 배열로 반환한다.
- 기존 backend는 `result.total_count`를 그대로 `totalCount`로 전달해 Ant Design Table의 `pagination.total`에 숫자가 아닌 값이 들어갈 수 있었다.

## Changes
- `backend/src/patent-analysis/patent-analysis.service.ts`
  - `total_count[0].total` 형태를 숫자로 정규화하는 `getTotalCount` 추가.
  - embodiment API의 `total_rows`, `modified_total_rows` 배열도 숫자로 정규화.
- `backend/src/patent-analysis/types/patent-analysis-helper.types.ts`
  - 외부 API의 실제 total 응답 shape를 타입에 반영.
- `frontend/src/pages/PatentAnalysisList.tsx`
  - frontend에서도 total 값 방어 정규화를 추가.

## External API Pagination Guide
- 요청 파라미터:
  - `num-rows-per-page`: 페이지 크기
  - `page-no`: 1부터 시작하는 페이지 번호
- 응답:
  - `partial_rows`: 현재 페이지 row 목록
  - `total_count[0].total`: 전체 row 수

## Patent PDF Proxy Report

_Source: `report_20260528_patent_pdf_proxy.md`_


## Date
- 2026-05-28

## Scope
- `patent_analysis_helper_api`의 `DOWNLOAD-FILE` operation을 이용해 특허 PDF를 frontend PDF viewer에 표시할 수 있도록 backend proxy endpoint를 추가했다.

## Background
- 외부 API의 `GET-PATENT-DATA` 응답은 `ocr_pdf_path`, `pdf_path`로 `/raid/...` 파일 시스템 경로를 내려줄 수 있다.
- 브라우저는 `/raid/...` 경로에 직접 접근할 수 없다.
- helper API는 `DOWNLOAD-FILE` operation에 `file_path`를 전달하면 Flask `send_file()`로 파일 바이너리를 내려준다.

## Backend Changes
- `backend/src/patent-analysis/patent-analysis-helper.client.ts`
  - binary stream download용 `download()` 메서드를 추가했다.
  - `responseType: 'stream'`으로 helper API 응답을 받는다.
- `backend/src/patent-analysis/patent-analysis.service.ts`
  - `downloadPatentPdf()` 추가.
  - `GET-PATENT-DATA`로 metadata를 조회한 뒤 `ocr_pdf_path`, `pdf_path`, `pdf_url` 순서로 파일 경로를 선택한다.
  - 선택된 path를 `DOWNLOAD-FILE` operation의 `file_path`로 전달한다.
- `backend/src/patent-analysis/patent-analysis.controller.ts`
  - `GET /api/patents/:publicationNumber/pdf` 추가.
  - helper API의 stream 응답을 `Content-Disposition: inline`으로 브라우저에 전달한다.

## Frontend Changes
- `frontend/src/services/patentAnalysisApi.ts`
  - `getPatentPdfUrl(publicationNumber)` 추가.
- `frontend/src/pages/PatentAnalysisDetail.tsx`
  - API metadata에 PDF path가 있으면 `/api/patents/:publicationNumber/pdf`를 PDF viewer document로 사용한다.
  - 브라우저 접근 가능한 직접 URL이 있으면 그대로 사용하고, `/raid/...` path는 backend proxy를 사용한다.

## Runtime Flow
```text
frontend PDF viewer
  -> GET /api/patents/:publicationNumber/pdf
backend
  -> POST helper /api operation=GET-PATENT-DATA
  -> POST helper /api operation=DOWNLOAD-FILE file_path=/raid/...
  -> stream PDF to browser
```

## 배경
- 특허 분석 목록의 구조 검색에서 `/api/patents/compound-search` 요청이 `408 Request Timeout`으로 실패한 뒤 화면이 로딩 상태에 머무르는 문제가 있었다.
- 구조 검색은 compound search 후 각 compound에 대해 `GET-PATENT-LIST-BY-COMPOUND-ID`를 추가 호출하므로 `size=100` 요청 시 backend timeout에 걸릴 가능성이 높다.

## 변경 사항
- `frontend/src/services/patentAnalysisApi.ts`
  - 공통 JSON 요청 함수에 `AbortController` 기반 timeout 옵션을 추가했다.
  - HTTP 에러 응답의 JSON body 메시지를 읽어 사용자에게 표시할 수 있도록 했다.
- `frontend/src/pages/PatentAnalysisList.tsx`
  - 구조 검색 요청에 35초 client timeout과 effect cleanup abort를 연결했다.
  - 구조 검색 page size는 원본 helper UX와 동일하게 compound 기준 100으로 분리했다.
  - 구조 검색 2페이지 이상에서는 `operation=GET-ELASTIC-COMPOUND-LIST-BY-PAGE`를 보내도록 했다.
  - 구조 검색 중에는 테이블 page size 변경을 숨겨 helper compound page와 화면 page를 1:1로 맞췄다.
  - 구조 검색 응답의 `raw.proof`를 개발자 콘솔에 summary/table 형태로 출력해 compound와 특허 연결 여부를 확인할 수 있게 했다.
  - 구조 검색 실패 시 경고 문구를 목록 조회 실패와 구분해서 표시한다.
- `backend/src/config/configuration.ts`
  - `PATENT_ANALYSIS_COMPOUND_SEARCH_PATENT_LOOKUP_LIMIT` 환경변수로 compound별 특허 역조회 최대 개수를 설정할 수 있게 했다.
  - 기본값은 20이다.
- `backend/src/patent-analysis/patent-analysis.service.ts`
  - 구조 검색 page가 2 이상이면 helper 호출 operation을 `GET-ELASTIC-COMPOUND-LIST-BY-PAGE`로 보정한다.
  - 구조 검색 pagination total은 helper의 selected type compound total hit 수를 우선 사용한다.
  - compound search 결과에서 특허 역조회에 사용할 compound id 수를 제한했다.
  - compound별 특허 조회는 `Promise.allSettled`로 처리해 일부 실패가 전체 구조 검색 실패로 번지지 않도록 했다.
  - `raw.proof`에 `compoundId`, `patentRowCount`, `publicationNumbers`를 포함해 어떤 구조 검색 compound가 어떤 특허 row를 만들었는지 추적 가능하게 했다.

## 참고
- backend global timeout 기본값은 `HTTP_TIMEOUT_MS=30000`이다.
- frontend 구조 검색 timeout은 backend timeout 응답을 받을 수 있도록 35초로 설정했다.
- helper 검색 페이지는 compound 기준이지만, 화면 row는 compound에 연결된 patent row로 변환해 표시한다. 따라서 한 페이지에 표시되는 patent row 수는 compound 100개에서 찾은 특허 수와 중복 제거 결과에 따라 달라질 수 있다.

## Patent Title Search 400 Fix

_Source: `report_20260528_patent_title_search_400_fix.md`_


## 배경
- 특허 제목만 입력해 검색할 때 `/api/patents/my?...&title=...` 요청이 400 Bad Request로 실패했다.
- 이전 backend 로그에 `EADDRINUSE`가 있었기 때문에, 컨테이너 안에서 최신 DTO가 반영되지 않은 기존 Nest 프로세스가 계속 요청을 받을 가능성이 있다.
- Ant Design `RangePicker`에서 `disabled`와 빈 `value` 조합 경고도 발생했다.

## 변경 사항
- frontend 특허 제목 검색 요청 파라미터를 `title`에서 호환용 `keyword`로 변경했다.
- backend `PatentListQueryDto`에 `keyword`를 허용했다.
- backend 검색 필터 생성은 `title ?? keyword`를 특허 제목 조건으로만 사용하도록 유지했다.
- 기간 직접설정이 아닐 때는 `RangePicker`를 렌더링하지 않도록 변경해 Ant Design 경고를 제거했다.

## 확인 필요
- backend 컨테이너가 `EADDRINUSE` 없이 최신 코드로 재시작되어야 한다.
- 최신 backend에서는 `keyword=WO2026104323A1`도 특허 제목 검색 조건으로 변환된다.
