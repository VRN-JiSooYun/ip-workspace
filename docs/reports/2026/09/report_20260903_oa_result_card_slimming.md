# 검색 결과 카드 정리 — 통지 번호 제거·통지일자 우측·서지 정보 접기

## 요구

1. `oa-result-top`의 `oa-result-action-number`를 지운다(사용자들이 필요 없다고 했다).
2. `oa-result-date-badge`를 우측 정렬한다.
3. `oa-result-footer`는 접기 버튼을 두고 기본은 접어 둔다.

## 1·2 — 머리줄: 제목 + 오른쪽에 모은 칩 둘

통지 번호를 빼면 머리줄 왼쪽이 빈다. 그 자리에 **제목을 올려** 한 줄로 만들었다 — 카드에서
먼저 읽는 것이 제목이니 맨 윗줄의 왼쪽이 그 자리다. 칩 둘은 오른쪽에 모으고 법적상태를 가장
끝에 뒀다.

    [제목 ....................]  [2025.01.14] [출원]
    영문 제목

`margin-inline-start: auto`는 칩 묶음의 첫 칩(통지일자)이 갖는다 — 앞의 칩이 자리를 밀어
둘이 함께 오른쪽으로 간다. 마크업 순서도 화면 순서(제목 → 일자 → 상태)와 같게 두었다.
`order`로 뒤집으면 읽는 순서와 보이는 순서가 어긋난다.

줄바꿈은 막았다(`flex-wrap: nowrap`). 허용하면 긴 제목이 칩을 다음 줄로 밀어내 "한 줄"
배치가 무너진다. 줄어드는 쪽은 제목이고(`flex: 1 1 auto; min-width: 0`), 칩은 제목의
**첫 줄**에 맞춘다(`align-items: flex-start`) — 가운데 정렬로 두면 제목이 두 줄일 때 칩이
줄 사이로 내려가 어느 줄에 딸린 것인지 흐려진다.

**아주 좁은 카드(컨테이너 380px 이하)에서는 칩을 아랫줄로 내린다.** 칩 둘이 140px 남짓을 늘
차지하므로 그대로 두면 제목이 한 줄에 두세 글자씩 끊긴다. 그때는 제목에 한 줄을 다 주고 칩은
그 아래 오른쪽에 붙인다.

### 제목이 옛 통지 번호 스타일을 물려받았다 — 색만 빼고

통지 번호가 빠지면서 카드에서 가장 큰 글씨가 없어져 위계가 납작해졌다. 이제 그 자리가
제목이므로 **크기·굵기(17px/700)** 를 물려받았다(제목은 15px/600이었다).

**색(`var(--brand-primary)`)은 물려받지 않았다.** 이유 둘.

- 흰 배경에서 대비가 **2.61:1**이다(측정값). 본문 글자 기준 4.5:1은 물론 큰 글자 기준
  3:1도 넘지 못한다. 짧은 식별자일 때는 넘어갈 수 있었지만 카드에서 가장 많이 읽는 줄에는
  쓸 수 없다. 지금 색(`--text-primary` #4F5D73)은 약 6.5:1이다.
  참고로 다크에서는 브랜드 색도 6.5:1이라 문제가 되는 것은 라이트뿐이다.
- 이 화면에서 브랜드 색은 hover·선택(카드 테두리·안쪽 링)을 뜻한다. 열 카드의 제목이 모두
  브랜드 색이면 어느 카드가 골라져 있는지가 흐려진다.

칩의 첫 줄 정렬값도 함께 손봤다(제목 줄 높이 22.5px → 25.5px, `margin-block-start` 1px →
2px). 측정한 칩 중심과 제목 첫 줄 중심의 차이는 0.1px다.

## 3 — 서지 정보 접기

여섯 항목(출원·공개·등록 번호와 일자)이 카드 높이의 3분의 1을 먹는데, 목록을 훑는 동안 보는
것은 제목과 거절이유다. 게다가 이 값들은 `includePatentDetail`로 따로 받아야 채워져 대개
`-`다. 그래서 카드마다 `출원·공개·등록 정보` 버튼을 두고 **기본은 접어** 둔다.

카드를 가로지르는 구분선은 이제 이 버튼 줄이 갖는다(예전에는 서지 정보 표가 갖고 있었다) —
표가 접혀 있어도 카드의 아래 단이 여기서 끝난다는 것이 보여야 한다. 화살표는 펼치면
180° 돌아간다.

### 카드 클릭과 부딪히지 않게

카드 자체가 `role="button"`이라 그 안의 버튼은 두 곳에서 새어 나간다.

- **클릭** — 토글의 `onClick`에서 `stopPropagation()`. 없으면 펼치려던 사람이 문서를 연다.
- **키보드** — 카드의 `onKeyDown`이 Enter·Space를 받아 문서를 열므로, 토글에서 올라온
  키 이벤트를 걸러야 한다. `event.target !== event.currentTarget`이면 무시한다 —
  버튼 자신의 Enter·Space는 브라우저가 클릭으로 바꿔 준다.

남는 한계: `role="button"` 안에 실제 버튼이 들어간 구조라 보조기술에서 중첩 상호작용으로
읽힌다. 카드 전체 클릭을 제목 링크로 바꾸면 없어지지만 요청 범위를 넘으므로 두었다.

## 검증

`office-action-harness.html`에서 확인했다.

| 확인 | 결과 |
| --- | --- |
| 통지 번호 | DOM에 `.oa-result-action-number` 0개 |
| 머리줄 순서 | `[제목][통지일자][출원 태그]` — 한 줄(높이 26px) |
| 제목 글씨 | 17px / 700, 색은 `--text-primary` 유지 |
| 우측 정렬 | 법적상태 오른쪽 끝과 머리줄 오른쪽 끝의 간격 **0px**, 통지일자는 그 왼쪽에 붙음 |
| 제목 | 머리줄 왼쪽 끝에서 시작(0px), 남는 폭을 모두 차지 |
| 긴 제목(카드 420px) | 제목이 네 줄로 접히고 **칩은 첫 줄에 그대로**, 가로 넘침 없음 |
| 좁은 컨테이너(360px) | 제목이 첫 줄을 다 쓰고 칩은 아랫줄 오른쪽(법적상태 끝 0px) |
| 기본 상태 | 서지 정보 없음, `aria-expanded="false"`, 카드 높이 **219px** |
| 펼침 | 6항목(출원번호·출원일자·공개번호·공개일자·등록번호·등록일자), 높이 322px |
| 다시 접기 | 표가 사라지고 `aria-expanded="false"` |
| 토글 클릭 | 카드가 **선택되지 않고** 레일도 그대로(빈 상태 유지) |
| 토글에서 Enter·Space | 카드가 선택되지 않음 |
| 카드 본문 클릭 | 선택되고 레일에 문서가 열림, 토글 상태는 그대로 |
| 카드 포커스 + Enter | 그 카드가 선택되고 레일이 그 문서로 바뀜(기존 동작 유지) |
