# 검색 조건이 바뀌면 자동으로 검색

## 요구

`oa-searchbar-conditions`(조합된 키워드 조건)에 변경이 생길 때마다 자동으로 검색한다.

## 왜 조건 목록은 자동이어도 되는가

조건 chip은 **이미 확정된 값**이다 — 입력 중인 글자가 아니다. 추가·삭제는 그때마다 "이
조건으로 다시 보여 달라"는 뜻이라 버튼을 한 번 더 누르게 할 이유가 없었다. 특히 chip의 ×로
조건을 지웠을 때는 누를 버튼이 화면 반대쪽에 있어, **지워 놓고도 옛 결과를 보고 있는 상태**가
되기 쉬웠다.

반대로 입력창의 draft는 자동 검색 대상이 아니다. 글자를 칠 때마다 matches API를 부르는
실시간 검색이 되면 안 된다. draft는 '조건 추가'나 Enter로 확정되어 목록에 들어온 뒤에만
검색을 부른다.

## 구현

`OfficeActionAnalysis`에서 조건 목록의 key(`officeActionKeywordLabel` 이어 붙임)를 보고
바뀔 때만 기존 검색 실행 경로(`requestKeywordSearch` → token → `runKeywordSearch`)를 부른다.

- 진입 시에는 부르지 않는다. ref를 첫 key(빈 목록)로 시작해 첫 render에서 같은 값이 되게
  했다 — 초기 목록은 기존의 '진입 시 1회' 로드가 맡는다.
- **제외 조건만 남은 상태에서는 부르지 않는다.** 서버가 거부하는 조합이고 안내는 검색 바가
  이미 띄우고 있다. 여기서 부르면 조건을 짜는 중에 경고 toast만 반복해 뜬다. 포함 조건이
  더해지는 순간 key가 다시 바뀌어 검색이 나간다.

### 검색 버튼이 하는 일이 갈렸다

버튼이 `addCondition()` + `onSearch()`를 함께 하던 자리라, 그대로 두면 draft를 확정할 때
**같은 검색이 두 번** 나간다. 그래서 둘로 갈랐다.

- 조건이 없고 입력창에만 낱말이 있으면 → 그것을 첫 포함 조건으로 확정만 한다(검색은 조건
  변화로 따라온다).
- 그 밖에는 → 지금 조건 그대로 다시 받는다(조건이 없으면 전체 목록). 버튼은 "같은 조건으로
  새로 받기"로 남는다.

기존 조건이 있는데 입력창에 낱말이 남아 있으면 버튼은 원래대로 잠겨 있다(AND/OR/EXCLUDE를
먼저 골라야 한다).

### 겹친 요청 방어

`runKeywordSearch`에 요청 번호를 붙여 **마지막 요청만 결과를 반영**하게 했다(늦게 도착한 옛
응답은 버리고 `loading`도 내리지 않는다). 버튼 클릭만 있던 때는 `loading` 중 버튼이 잠겨
겹칠 일이 없었지만, chip을 잇달아 지우면 요청이 겹칠 수 있다.

## 검증

`office-action-harness.html`에서 `/patent-search`(matches) 호출 수를 세며 측정했다.

| 동작 | 조건 | 결과 | 추가 호출 |
| --- | --- | --- | --- |
| '조건 추가'로 첫 조건 확정 | `EGFR` 포함 | 137 → 10 | **1** |
| 드롭다운 AND로 둘째 조건 | +`억제제` 포함 | 10 | **1** |
| chip 1개 × 삭제 | `EGFR`만 | 10 | **1** |
| 마지막 chip × 삭제 | 없음 | 10 → **137 복귀** | **0** (키워드가 없으면 인덱스로 다시 세운다) |
| 포함 조건을 지워 '제외만' 상태 | `보정` 제외 | 그대로 | **0** + 경고 문구 표시, toast 없음 |
| 검색 버튼(조건 없음 + draft) | `KRAS` 포함 | 10 | **1** (두 번 나가지 않음) |
| 검색 버튼(조건 그대로) | 그대로 | 10 | **1** |
| 입력창 Enter | +`억제제` 포함 | — | **1** |

레일에 열어 둔 문서는 자동 검색 뒤에도 그대로 남는다(문서를 치우는 자리는 화면을 떠날 때
하나뿐이라는 기존 규칙이 유지된다) — 타임라인까지 그대로 확인했다.

harness 10/10 통과(측정은 viewport를 준 상태에서 해야 한다 — 패널이 접혀 있으면 높이 검사
두 개가 0으로 읽혀 실패한다). `tsc -b --force` 관련 오류 없음.
