# 레일 문서는 목록 조작으로 닫히지 않는다

## 작업 목적

우측 레일에 문서를 열어 둔 채 의견제출통지서 목록의 **페이지를 넘기거나 한 페이지 크기를
바꾸면** 열어 둔 문서가 사라졌다. 목록을 훑는 동안 문서를 곁에 두는 것이 이 레일의 목적인데,
그 목적이 목록 조작만으로 깨졌다.

고치면서 규칙을 하나로 정리했다. **문서를 치우는 자리는 화면을 떠날 때 한 곳뿐이다.**

## 원인

`OfficeActionAnalysis`의 목록 갱신 경로가 **무조건** 레일을 비우고 있었다.

```ts
// applyClientFilters(...)  ← 조건 적용과 페이지 이동이 같이 쓴다
// runKeywordSearch(...)
pendingDocumentIdRef.current = null;
clearDocuments(DOCUMENT_SOURCE, { keepPanelOpen: true });
```

원래 근거는 "목록이 바뀌면 이전 선택은 더 이상 화면에 없을 수 있다"였다. 하지만 레일은
목록의 미리보기가 아니라 **따로 여는 작업 공간**이다. 지금 결과에 없는 문서가 열려 있는 것은
이상한 상태가 아니고, 목록을 이리저리 바꿔 가며 같은 문서를 보는 것이 오히려 이 기능의 쓰임이다.
페이지 이동은 같은 결과 안에서 보는 구간만 옮기는 일이라 더더욱 닫을 이유가 없다.

## 변경 내용

`frontend/src/pages/OfficeActionAnalysis.tsx`

- 목록 갱신 경로(`applyClientFilters`, `runKeywordSearch`)의 `clearDocuments` 호출을 **모두
  제거**했다. 페이지 이동·한 페이지 크기 변경·상세 필터 적용·새 키워드 검색 어느 것도 열어 둔
  문서를 건드리지 않는다.
- `clearDocuments`가 남은 곳은 **언마운트 effect 하나**다. 화면을 떠날 때만 이 화면이 올린
  문서를 치운다(다른 화면이 이미 채웠으면 그대로 둔다 — store의 `source` 규칙).
- 그 effect 주석에 규칙을 적어 두었다. 다음에 "목록이 바뀌었으니 정리하자"는 판단이 다시
  들어오는 것을 막는 자리가 필요하다.
- 목록에 없는 문서가 열려 있으면 카드 강조(`selectedId`)만 사라지고 뷰어는 유지된다. 강조는
  레일 store에서 읽으므로 따로 손댈 것이 없다.

## 검증 결과

`frontend/office-action-harness.html`, 1500×1000. 문서를 연 뒤 각 조작을 하고 레일을 확인했다.

| 동작 | 결과 목록 | 레일 문서 |
| --- | --- | --- |
| 문서 열기 | 137건 | `9-5-2025-000100000` 표시 |
| 2페이지로 이동 | 카드가 `…00010`부터 | 유지 |
| 한 페이지 30건으로 변경 | 카드 30장 | 유지 |
| 상세 필터(의견서 유무=`무`) | 137건 유지 | 유지 |
| 상세 필터(의견서 유무=`유`) | **0건** | 유지 |
| 새 키워드 검색(`EGFR`) | 조건 chip 추가, 재계산 | 유지 |

harness 자동 점검 10개 전부 통과, `tsc -b --force` 통과.

화면 이동 시 정리는 언마운트 effect 그대로라 이번 변경의 영향이 없다(harness는 이 화면만
띄우므로 그 경로는 코드 검토로 확인했다).

## 미실행 항목

- 결과에 없는 문서가 열려 있을 때 그 사실을 알리는 표시는 두지 않았다. 카드 강조가 없는 것으로
  이미 드러나고, 목록 조작마다 안내가 뜨면 시끄럽다.
- 특허 관리 화면 등 다른 `source`가 올린 문서에는 이 변경이 닿지 않는다. 각 화면이 자기
  `source`만 치우는 store 규칙은 그대로다.
