# Office Actions 키워드 조건 빌더 통합 작업 보고서

## 작업 목적

`oa-searchbar`의 단일 문서·단일 검색어 입력과 상세 필터의 문서 전문 키워드 영역이 분리되어
있던 구조를 하나의 키워드 조건 빌더로 통합한다. 사용자가 검색 대상 문서와 연산자를 직접
선택하고 여러 조건을 조합한 뒤 한 번에 검색할 수 있도록 한다.

## 변경 내용

- 검색바에 검색 대상 문서, `AND · 포함` / `NOT · 제외` 연산자, 본문 키워드 입력을 배치했다.
- `조건 추가`로 여러 조건을 조합하고, 조건 pill의 닫기 버튼으로 개별 삭제할 수 있게 했다.
- 입력 중 `검색` 또는 Enter를 실행하면 현재 draft 조건을 먼저 추가한 뒤 최신 조건으로
  검색하도록 기존 지연 적용 흐름과 연결했다.
- 제외 조건만 있는 경우 상류 API가 반대 의미로 처리하는 문제를 막기 위해 경고를 표시하고
  검색을 비활성화했다.
- 상세 필터의 `oa-subpanel-grid-keyword`와 관련 draft·tag UI를 제거했다.
- 키워드 조건 상태를 상세 필터 상태에서 분리해 상세 필터 초기화가 키워드 조건을 지우지
  않도록 했다.
- 조건 정규화와 API 변환을 `officeActionKeywords.ts`로 분리하고, 관련 API 문서의 구현 경로를
  갱신했다.
- 검색바는 자체 컨테이너 폭에 따라 1행, 2행, 모바일 3행 구조로 재배치되도록 구성했다.

## 검증 결과

- 검색 대상은 의견제출통지서, 의견서, 보정서 세 종류를 유지한다.
- 상류 API에서 정상 동작하는 `AND`, `NOT`만 UI에 노출하며 오류가 발생하는 `OR`은 노출하지
  않는다.
- 포함 조건은 API 배열 앞쪽에 배치하고 동일 조건은 중복 전송하지 않는 기존 규칙을 유지한다.
- 변경 파일의 diff와 공백 오류를 확인했다.

## 미실행 항목

- 저장소 지침에 따라 빌드 및 실행 기반 화면 확인은 수행하지 않았다.
