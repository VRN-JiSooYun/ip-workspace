# Office Action 명시적 검색과 Enter 필터 적용

## 작업 목적

새 키워드 목록을 서버에서 조회하는 동작과 이미 받은 목록을 상세 필터로 거르는 동작을 분리한다.

## 변경 내용

- `POST /api/patent-search`는 검색바의 `검색` 버튼을 클릭했을 때만 호출하도록 분리했다.
- 검색어 입력창의 Enter는 draft 키워드를 조합 조건에 추가할 뿐 서버 검색을 실행하지 않는다.
- 검색 버튼 클릭 시 경량 matches endpoint에서 전체 OA ID와 관련도를 한 번에 받아 브라우저의 기준 목록으로 교체한다.
- Search API 결과를 content 없는 OA 인덱스와 OA ID로 결합해 대리인, 심사진행상태, IPC 등 상세 필터용 구조를 유지한다.
- 상세 필터의 `조건 적용`, 필터 내부 Enter, 조건 초기화 후 적용, 페이지 이동은 마지막 기준 목록을 프런트에서 필터링하고 분할한다.
- 법조문·IPC draft 영역에서 Enter를 누르면 draft 조건을 먼저 추가하고 다음 render에서 최신 조건을 적용한다.
- 키워드가 없는 상태에서 검색 버튼을 누르면 전체 OA 인덱스를 기준 목록으로 복원한다.

## 호출 흐름

1. 화면 진입 시 content 없는 OA 인덱스를 한 번 받아 기본 목록을 구성한다.
2. 사용자가 키워드 조건을 편집하거나 Enter로 추가하는 동안 Search API는 호출하지 않는다.
3. 사용자가 `검색` 버튼을 클릭하면 단일 matches 응답으로 기준 목록을 갱신한다.
4. 이후 상세 필터 적용과 페이지 이동은 기준 목록에 대한 프런트 처리만 수행한다.

## 검증 결과

- 검색 버튼과 상세 필터 적용에 서로 다른 event token 및 실행 함수를 사용하도록 호출 경계를 분리했다.
- 상세 필터와 페이지 변경 경로에 `patentSearchApi.search()` 호출이 없음을 정적으로 확인했다.
- 키워드 입력 Enter가 `onSearch`를 호출하지 않는 것을 확인했다.
- 변경 diff의 공백 오류를 확인했다.

## 미실행 항목

- 저장소 지침에 따라 빌드, 테스트 및 개발 서버 실행은 수행하지 않았다.
