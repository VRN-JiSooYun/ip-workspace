# docs 문서 정보 구조 정리

## 목적

- `docs/` 루트에 누적된 날짜별 보고서를 에이전트와 개발자가 빠르게 탐색할 수 있도록 정리한다.
- 새 문서가 다시 루트에 쌓이지 않도록 저장 위치와 명명 규칙을 명확히 한다.

## 변경 내용

- 날짜 보고서 121개를 `docs/reports/YYYY/MM/`로 이동했다.
- 날짜 기반 계획 문서를 `docs/plans/YYYY/MM/`로 이동했다.
- `docs/README.md`를 문서 진입점, 검색 순서, 명명 규칙 중심으로 개편했다.
- `docs/reports/README.md`와 `docs/plans/README.md`를 추가했다.
- `AGENTS.md`의 문서화 규칙에 새 경로를 반영했다.
- 기존 문서에서 직접 참조하던 날짜 보고서 경로를 새 위치로 수정했다.

## 선택한 구조

- 요일별 분류는 날짜의 고유성이 없고 시간이 지날수록 같은 요일 문서가 섞이므로 사용하지 않는다.
- 일자별 폴더는 파일 하나 또는 소수 파일을 위해 디렉토리 깊이를 늘리므로 사용하지 않는다.
- 연/월 폴더는 한 폴더의 파일 수를 제한하면서도 날짜순 정렬과 주제 검색을 모두 지원한다.
- 같은 날의 문서는 독립 작업 단위를 보존하기 위해 강제로 병합하지 않는다.

## 검증

- 날짜 보고서가 `docs/` 루트에 남아 있지 않은지 확인한다.
- 날짜 보고서의 월별 파일 수와 전체 파일 수를 이동 전후로 비교한다.
- Markdown의 기존 `docs/report_YYYYMMDD...` 경로가 남아 있지 않은지 검색한다.

## 실행 여부

- 문서 정리 작업이므로 애플리케이션 빌드 및 실행은 수행하지 않았다.
