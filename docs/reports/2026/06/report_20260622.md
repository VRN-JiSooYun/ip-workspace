# 2026.06.22 작업 보고서

## 특허 분석 상세 크게보기 Ligand 3D 버튼 제거

### 배경
- 특허 분석 상세 페이지에서 화합물 구조를 크게 볼 때 `Ligand 3D 보기` 버튼이 표시되고 있었다.
- 현재 특허 상세 데이터는 SMILES를 SDF conformer로 변환해 3D viewer에 안정적으로 전달할 수 있는 데이터 계약이 아니므로, 특허 상세 페이지 전체에서 3D 전환 버튼을 숨길 필요가 있었다.

### 변경 내용
- `frontend/src/components/common/StructurePreviewModal.tsx`
  - `enableLigand3d` prop을 추가하고 기본값은 `true`로 유지했다.
  - `enableLigand3d`가 `false`이면 `Ligand 3D 보기` 버튼을 렌더링하지 않는다.
  - 비활성 상태로 전환될 때 진행 중인 ligand conformer 요청과 3D preview 상태를 정리한다.
- `frontend/src/pages/PatentAnalysisDetail.tsx`
  - 특허 상세 페이지의 공통 구조 preview modal 호출부에서 `enableLigand3d={false}`를 전달해 모든 특허 상세 크게보기에서 `Ligand 3D 보기` 버튼을 숨긴다.

### 기대 효과
- 특허 분석 상세 페이지의 모든 화합물 크게보기에서는 `Ligand 3D 보기` 버튼이 보이지 않는다.
- 공통 구조 preview modal을 사용하는 다른 화면의 기존 3D 기능은 유지된다.

## 특허 분석 상세 PDF bbox 초기 로드 위치 안정화

### 배경
- 특허 상세 페이지 첫 로드 시 PDF `page-width` 스케일과 highlight layer 레이아웃이 완전히 확정되기 전에 bbox highlight가 먼저 배치되면, 실제 bbox 근처에 어긋난 위치로 표시되는 경우가 있었다.
- 새로고침 후에는 PDF layer가 안정화된 상태에서 다시 계산되어 정상 위치로 보이는 현상이 있었다.

### 변경 내용
- `frontend/src/hooks/usePatentPdfViewer.ts`
  - data bbox highlight id에 `highlightLayoutRevision`을 포함해 PDF scale/page render 이벤트 이후 highlight가 강제로 remount되도록 했다.
  - active compound bbox highlight도 `dynamicHighlights` 조합 단계에서 layout revision을 id에 반영해 초기 배치 캐시를 재사용하지 않도록 했다.
  - bbox 선택 매칭은 기존처럼 `source.baseId` 기준을 유지해 클릭/선택 상태 로직은 변경하지 않았다.
- `frontend/src/pages/PatentAnalysisDetail.tsx`
  - `source.baseId`가 없는 fallback 선택 경로에서도 `__layout_N` suffix를 제거해 기존 base id 기준과 맞추도록 보강했다.

### 기대 효과
- 첫 로드 중 PDF page-width 스케일이 뒤늦게 확정되어도 bbox highlight가 최종 레이아웃 기준으로 다시 배치된다.
- 새로고침해야 bbox가 정상화되는 빈도를 줄인다.

## Raw/Clean Data 구조 컬럼 페이지 이동 이벤트 보정

### 배경
- Summary의 추천 Key Compound 카드는 좌/우 버튼으로 `p.{number}` compound 페이지 이동이 정상 동작했다.
- Raw Data table의 Structure 컬럼에서는 좌/우 버튼 클릭 시 버튼 핸들러 실행 뒤 Ant Design table row 클릭 이벤트가 이어서 실행되어, 렌더 당시의 이전 `curIdx` 기준 페이지로 다시 이동하는 현상이 있었다.

### 변경 내용
- `frontend/src/pages/PatentAnalysisDetail.tsx`
  - Raw Data table Structure 컬럼의 이전/다음 버튼 `onClick`에서 `event.stopPropagation()`을 호출하도록 수정했다.
  - 같은 table row 클릭 구조를 사용하는 Clean Data table Structure 컬럼의 이전/다음 버튼도 동일하게 보정했다.

### 기대 효과
- Raw Data/Clean Data table의 Structure 컬럼 좌/우 버튼 클릭 시 row 클릭 핸들러가 중복 실행되지 않는다.
- 버튼 라벨 `p.{number}`와 실제 PDF 이동 페이지/bbox가 같은 index 기준으로 유지된다.

- 다른 컬럼을 클릭하는 기존 row 상세 이동 동작은 유지된다.

## 특허 리스트 Key Scaffold PPT 링크 복사

### 배경
- 열린 PowerPoint에 직접 삽입하는 방식은 웹앱 단독으로 안정적으로 처리하기 어렵다.
- 빠른 구현 방식으로 구조 이미지를 클립보드에 복사하되, HTML anchor 링크를 함께 담아 PowerPoint에 붙여넣은 이미지 클릭 시 MyWorkspace로 돌아오도록 구성했다.

### 변경 내용
- `frontend/src/components/common/CompoundStructureView.tsx`
  - SVG를 PNG blob/data URL로 변환한 뒤 `text/html`, `text/plain`, `image/png` clipboard payload를 작성하는 `copyLinkedSvgImageToClipboard` 유틸을 추가했다.
  - HTML payload는 `<a href="..."><img ... /></a>` 형태로 생성한다.
- `frontend/src/pages/PatentAnalysisList.tsx`
  - `publicationNumber` URL query param을 읽어 특허 번호 검색 상태로 리스트를 초기화하도록 보강했다.
  - Key Scaffold 구조 카드에 `PPT 링크 복사` action을 추가했다.
  - 복사 링크는 `/patents/analysis?publicationNumber={patentNumber}&focus=keyScaffold` 형식으로 생성한다.

### 기대 효과
- 특허 리스트 Key Scaffold 구조에서 `PPT 링크 복사` 버튼을 누른 뒤 PowerPoint에 붙여넣으면, 가능한 환경에서는 클릭 가능한 구조 이미지로 붙여넣어진다.
- PPT의 구조 이미지 링크를 열면 MyWorkspace 특허 리스트가 해당 특허 번호 검색 상태로 열린다.

### 참고
- PowerPoint의 클립보드 HTML hyperlink 유지 여부는 OS/브라우저/PowerPoint 버전에 따라 달라질 수 있다.
- HTML hyperlink가 유지되지 않는 환경에서는 이미지 또는 링크 텍스트만 붙을 수 있다.
